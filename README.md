# Gopher-Key-Value-Storage

Отказоустойчивая распределенная in-memory база данных, написанная с нуля на Go.Использует алгоритм консенсуса Raft для управления репликацией логов. Обеспечивает Строгую консистентность (Strong Consistency) при записи данных через лидера и Eventual Consistency при чтении с узлов-фолловеров.

## Главные фичи

* **Алгоритм Raft:** Полная реализация Leader Election (выборы лидера) и Log Replication. Система успешно переживает потерю связи между нодами.
* **Шардирование в памяти:**: Хранилище разбито на массив из 256 независимых сегментов со своими sync.RWMutex. Это кардинально снижает вероятность Lock Contention и позволяет эффективно распределять конкурентную нагрузку при тысячах параллельных запросов. 
* **Свой WAL (Write-Ahead Log):** Гарантия сохранности данных (Durability). Ноды могут безопасно восстанавливать свой стейт, терм и логи после жесткого падения или отключения питания.
* **Умный HTTP-роутинг:** Клиент может отправлять запросы к *любой* ноде. Фолловеры выступают в роли **Reverse Proxy**, автоматически перенаправляя запросы на запись к текущему Лидеру.
* **Observability (Мониторинг):** Встроенный сбор кастомных метрик (`raft_state`, `raft_term`, `raft_commits`) через **Prometheus** с готовой интеграцией под **Grafana**.
* **Тестирование:** покрытие E2E-тестами, включая симуляцию краш-рекавери.

## Архитектура

1. **Storage Layer:** Высокопроизводительное in-memory хранилище. Реализовано **шардирование** в памяти (256 сегментов/shards)** с независимыми `sync.RWMutex` для кардинального снижения lock contention при высоких конкурентных нагрузках.
2. **Consensus Layer (Raft):** Управление переходами состояний (Follower -> Candidate -> Leader) и кворумом. Обеспечивает **Strong Consistency** при записи и **Eventual Consistency** при чтении с фолловеров.
3. **Durability Layer (WAL):** Бинарный append-only лог для команд и отдельный легковесный лог метаданных для хранения термов, голосов и индекса последней закомиченной команды.
4. **Transport Layer:** **gRPC** для сверхбыстрого внутреннего P2P-общения нод кластера, **HTTP REST** для внешнего клиентского API.

##  Запуск
## Запуск с помощью Docker
1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Chaice1/Gopher-Key-Value-Storage.git
    ```

2.  **Перейдите в директорию проекта:**
    ```bash
    cd Gopher-Key-Value-Storage
    ```
3.  **Запуск программы:**
    ```bash
    make run
    ```
4.  **Остановка работы программы:**
    ```
    make stop 
    ```
5.  **Остановка работы программы и удаление volumes:**
    ```
    make stop-volumes
    ```
Подождите пару секунд, пока ноды проведут выборы Лидера.
Доступ к HTTP API нод открыт на портах 8083, 8084 и 8085

##  Использование API
**В кластере работает умный роутинг (Reverse Proxy).**Не нужно знать**, кто сейчас Лидер — просто отправляй запросы в любую ноду, а кластер сам перенаправит запрос под капотом!**
**1. Запись данных**
```bash
curl -X POST http://localhost:8083/set \
     -H "Content-Type: application/json" \
     -d '{"key": "gopher", "val": "is_awesome"}'
```
**2. Чтение данных **
```bash
curl -s -X GET "http://localhost:8084/get?key=gopher"
```
**3. Удаление данных **
```bash
curl -X DELETE http://localhost:8085/delete/gopher
```
